Zerobus sink: only known bad-data errors (encoding_failed, invalid_argument, grpc_invalid_argument) on a single batch on a stream that stays open reject it. A server rejection closes the stream, so it, the same codes from stream setup, and every other non-retryable error now return Errored at once; a stream the failure closed (including a poisoned multiplexed stream) is always discarded, and a batch it was closed under is sent once more on a fresh stream before it is answered. New zerobus_errored_batches_total{error_code} counts every Errored batch. aws_s3 source: failed SQS messages (sink-errored batches, GetObject failures, transient read errors) are now released on a backoff (errored_message_release, on by default) instead of always waiting a full visibility timeout.
