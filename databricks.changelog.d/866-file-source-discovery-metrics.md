Add two file-source discovery metrics, shared by the `file` and `kubernetes_logs` sources (ES-2271421). `file_discovery_passes_delayed_total` counts discovery passes slow enough that the back-off from #817 pushed the next pass past its schedule (passes taking more than half of `glob_minimum_cooldown`; not counted for a zero cooldown). `file_discovery_last_pass_timestamp_seconds` is a per-source gauge of when the last discovery pass finished, in unix seconds, set when the file server starts and after every pass, so `time() - x` is the age of a source's discovery and every running source reports it. The file server holds the gauge's handle for as long as it runs, and Vector does not expire a metric with a live handle, so a server stuck in a pass, a drain or a blocked send keeps exporting its last, increasingly stale, timestamp; once a removed source's server exits, the gauge expires normally. Also fixes a race in the `file_start_position_server_restart_unfinalized` test, which dropped its first run's unacknowledged events while that run's file server could still be writing its final checkpoint. https://github.com/databricks-eng/vector/pull/866
