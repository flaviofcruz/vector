Add `file_backlog_max_age_seconds`, a per-source gauge of how far behind the `file` and `kubernetes_logs` sources are on the files they watch, set after every discovery pass (zero when every file is caught up). For each watched file with unread bytes (a read position below the size the last discovery pass saw; for a gzipped file, whose position counts decompressed bytes, not yet read to the end), the age is `now - mtime`: a lower bound on the age of its oldest unread byte, since the newest write happened at the mtime. A file that is still being written reads close to zero however far behind it is, but once writes stop (for example after an hourly file rotates) its unread backlog ages, so falling more than an hour behind on hourly files shows up once they have rotated and been compressed. The age comes from the stat discovery already takes, with no extra I/O and nothing added to the read path; files the watcher skips are not counted. Alongside it, `file_backlog_behind{over="900s"|"3600s"}` is set to 1 when that age is past the threshold and 0 otherwise, always emitted, so `avg` across sources is the fraction behind and `sum` the number behind. https://github.com/databricks-eng/vector/pull/872
