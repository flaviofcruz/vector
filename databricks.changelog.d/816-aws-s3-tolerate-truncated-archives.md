Add the `tolerate_truncated_archives` option (default off) to the `aws_s3` source's `sqs` config, mirroring the `azure_blob` option from #730. A gzip/zstd object whose bytes end mid-member decodes up to the tear and then errors `UnexpectedEof`; because the object is immutable, the SQS message is never deleted and redelivers forever, re-ingesting the decodable prefix as duplicates each cycle. When enabled, the shared `TolerateTrailingEof` wrapper turns a trailing `UnexpectedEof` after decoded output into a clean end-of-stream, so the source ingests complete decoded records, deletes the message, and emits `ObjectStorageBlobTruncated` (`cloud=aws`). The same guards apply: an undecodable body with no output still redelivers, transport errors stay `ErrorKind::Other`, every short transfer (compressed bytes pulled < `Content-Length`) redelivers, delimiter-based framing drops an unconfirmed final record, and a partial length-delimited frame remains an error.
