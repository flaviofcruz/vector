Switch the `databricks_zerobus` sink's `login_service` auth from Login's internal OAuth token RPC to `PrincipalContextService/CreatePrincipalContext`. Each bootstrap makes an unsigned call, whose `principal_context` UC `getTable` reads from `s2s-principal-context-bin`, and a signed call (`PCTX_DP_AUTH_TOKEN`, SSP path, metastore), whose `signed_principal_context` wrapper is sent to Zerobus as `s2s-principal-context-sig-bin`. Neither UC nor Zerobus is sent a bearer token any more. The pair is cached until the earlier `authentication_details.token_expiration` (50-minute default if unset). Config: `login_service.oauth_proto_descriptor_path` is renamed to `proto_descriptor_path` and must point at a `PrincipalContextService` descriptor; new required `metastore_id` and optional `zerobus_ssp_resource_path` (default `workspaces/<workspace_id>/zerobusDirectWriteApi`). The pinned Zerobus SDK cannot send `-bin` headers, so the sink now rejects `login_service` at startup (config validation) instead of discarding every batch at stream creation; the check is removed once the SDK sends `-bin` headers as binary metadata. The OAuth strategy is unchanged. https://github.com/databricks-eng/vector/pull/838
