Add a `variant_message_encoding` option to the `wire_to_arrow` codec. `spark` and `spark_strip_nulls` encode a VARIANT column backed by a nested proto message the way the classic variant union does (`to_variant_object(from_protobuf(...))`, optionally followed by `variant_strip_nulls`): native binary and float values, Spark's integer and enum handling, unset fields as null keys, proto3 defaults written out, unknown closed-enum numbers dropped before merging as protobuf-java does, and rows missing a `required` field dropped. Under `on_wire_type_mismatch: skip_field` a wire-type-mismatched field inside the message is left out before decoding, as protobuf-java treats it as unknown; `drop_row` drops the row. The default, `proto_json`, keeps today's output.
