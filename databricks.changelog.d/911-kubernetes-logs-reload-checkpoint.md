Fix a loss window in `kubernetes_logs` shutdown checkpointing: a line's checkpoint was recorded when the event loop read the line, so lines the event loop dropped when its sends hit the shutdown deadline were still covered by the final checkpoint and were lost. Checkpoint updates are now held back and committed only after each batch of events has been sent, so lines dropped at the deadline are re-read by the next source instance instead of lost. The final checkpoint's ordering fix itself landed in https://github.com/databricks-eng/vector/pull/754.
