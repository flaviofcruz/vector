Add `lp_unwrap!(value, wrapper_descriptor_file, log_entry_descriptor_file)`, a native one-pass replacement for the Lumberjack Prime stage-1 unwrap VRL chain (`decode_base64!` → `parse_proto!(LogDaemonWrapper)` → `decode_zstd` → `parse_proto(LogEntry)` → five stashes). It base64-decodes with VRL's rule, decodes both protobufs with the same prost-reflect path `parse_proto` uses (so the objects are identical on every input), attempts zstd only when the bytes carry a frame magic, and writes `._lp_inner_bytes`, `._lp_log_entry`, `._lp_log_entry_parsed`, `._lp_log_daemon_wrapper` and `._workspace_id` directly onto the event, declaring them to the type checker. Unused until a config calls it; universe gates the call per event behind the `databricks.logging.lumberjackPrimeNativeUnwrap` SAFE flag. Measured on a dev pod against a sibling on the stock image (same cluster, traffic and base, 2 h): unwrap stage 95 → 58 CPU-s per 1M events (−39%), whole container −15%, output rows identical. https://github.com/databricks-eng/vector/pull/839
