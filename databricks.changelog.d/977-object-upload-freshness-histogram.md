Added a Lumberjack Prime freshness histogram, `zerobus_ack_object_uploaded_to_saved_seconds{table}`, whose clock starts at the blob's object-storage write time (S3 `last_modified`, Azure blob `Last-Modified`, GCS object `Last-Modified`) and stops at the Zerobus ack. Queue sources stamp the time as `%databricks.object_uploaded_ms` event metadata, so no table schema change is needed for wire_to_arrow tables. Stamps of rows dropped by wire_to_arrow are kept out of the histogram. The new histogram uses SLO bucket edges (1 s to 2 h, +Inf) via a per-metric-name bucket override in vector-core, so the alert threshold can move by changing only the alert rule. Existing freshness metrics are unchanged.
