The wire-to-Arrow codec now skips a proto field whose wire type disagrees with the descriptor and keeps the row (protobuf-java semantics), instead of dropping the whole row. The behavior is controlled by a new `on_wire_type_mismatch` wire-to-Arrow serializer option (`skip_field` by default, `drop_row` restores the old behavior exactly), skips are counted by the `wire_to_arrow_fields_skipped_total` metric, and optional `attribution_fields` sample producer identifiers into the skip/drop warnings. The policy also covers message-backed VARIANT columns — a mismatched field inside a VARIANT sub-message is omitted from the Variant under `skip_field`, including when the sub-message falls back to the reference decoder for a map or well-known type — and a mismatched occurrence of an unprojected oneof member no longer clears a well-typed sibling (it is skipped and counted like any other mismatch). Under `skip_field`, rows that carry a mismatched field (including a map field) and also need duplicate-field or oneof normalization are kept; the decode guard now runs on bytes with mismatches stripped, so a malformed value is dropped regardless of where mismatches sit in the row. Skips are only counted for rows the batch keeps. Groups (wire types 3/4) still drop the row under both modes, unlike protobuf-java, which skips them as unknown fields.
