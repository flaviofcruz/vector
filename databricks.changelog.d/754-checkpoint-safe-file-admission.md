Add an optional generic FileServer admission transaction that reserves before reading, preserves per-file send and acknowledgement order, rewinds rejected or cancelled work, and checkpoints only acknowledged records. An admitted file's ready records go out as one acknowledged run, and a rewind refuses a path that now holds a different (rotated) file. The Kubernetes logs source now writes its final checkpoint only after its event loop has drained the file server's output, so a config reload no longer re-delivers lines that were still in flight. Production sources remain unenrolled until an admission adapter is configured.
