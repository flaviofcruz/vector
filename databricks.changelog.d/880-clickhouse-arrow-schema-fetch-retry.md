clickhouse sink: retry the startup ArrowStream schema fetch (`system.columns`) with exponential backoff before falling back to JSONEachRow, so one transient failure (connection reset, truncated body, timeout, or a retriable 408/429/5xx such as a `clickhouse-proxy`-relayed `TOO_MANY_SIMULTANEOUS_QUERIES`) no longer pins the sink to JSON for the life of the pod. Each attempt is bounded by `request.timeout_secs` (previously the fetch had no timeout), and the backoff starts at `request.retry_initial_backoff_secs`, doubling, capped at `request.retry_max_duration_secs`. 4xx, `non_retriable_error_codes`, and unparseable or unsupported schemas still fall back immediately. New optional `arrow_schema_fetch_max_attempts` (default 3, allowed 1–10; `1` disables retries) so universe can tune attempts per region without a binary release. Sinks build one at a time, so retries delay topology start. Each retry logs a warning and increments `clickhouse_arrow_schema_fetch_retries_total`, and non-200 schema errors now include a body excerpt.
